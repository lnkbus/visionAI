# VisionAI — 온프레미스/SaaS 하이브리드 음성 AI 플랫폼 (레고블록 모듈 아키텍처)

> 주식회사 링버스(LNKBUS) · B2B 설계/기획 문서 v2.0 · 2026-08
> 기준 사양: 「온프레미스 실시간 다국어 STT/TTS & sLLM AI 플랫폼 개발 사양서 v1.0」

## 프로젝트 개요

**VisionAI**는 폐쇄망(Air-Gapped) 온프레미스와 SaaS 양쪽으로 공급 가능한
**엔터프라이즈 실시간 음성/텍스트 AI 플랫폼**이다.

- 핵심 도메인: **금융 AICC**(실시간 상담원 지원) + **공공 스마트 회의록**
- 실시간 다국어 STT/TTS, Micro-Rule 컴플라이언스 필터, sLLM 기반 실시간 TA(Agent Assist)/RAG
  지식 팝업, 자동 요약 파이프라인을 단일 플랫폼으로 제공
- 향후 **AI 가상상담원(아바타 상담)**으로 확장

### 핵심 아키텍처 전략

1. **레고블록 모듈(Composable & Billable Blocks)** — 모든 컴포넌트는 독립 배포·조립 가능한
   블록이며, 동시에 **견적서 라인 아이템·라이선스 게이팅 단위**다. 블록 조합(bundle)으로
   제품 패키지(AICC / 회의록 / 가상상담원)를 구성하고, 업셀은 라이선스 파일 재발급으로 완결
2. **Model-Agnostic 어댑터** — STT(Faster-Whisper↔Triton), TTS(CosyVoice/Kokoro),
   sLLM(vLLM↔상용 API)을 코드 수정 없이 핫스왑
3. **Dual-Profile + Sub-Second** — AICC(초저지연 Stereo/RTP)와 회의록(고정밀 Mono/File)
   동시 지원, STT→RAG 지식 팝업까지 1초 미만
4. **Complete Air-Gapped** — H/W Fingerprint 오프라인 DRM, KCMVP 암호화, 외부 호출 0건.
   동일 코드가 SaaS에서는 상용 API Provider로 동작

## 현재 구현 상태 (Wave 1~5 완료, Wave 6 진행 중)

**고객이 질문하면 1초 안에 상담원 화면에 근거 팝업이 뜬다** — 사양서의 핵심 경로가 동작한다.

```
전화(RTP/G.711) ┐
마이크(WebSocket) ┴→ VAD → STT(+커스텀 사전) → 컴플라이언스 필터(<10ms)
      → 질의 추출(SLM) → 하이브리드 검색(Dense+BM25) → 리랭킹 → 지식 팝업
      → 통화 종료 시 자동 요약
```

|------|------|------|

### 고객사가 직접 운영하는 화면 (`SCN-STUDIO`)

온프레미스 B2B에서 룰 한 줄 바꾸는 데 공급사 인력이 필요하면 유지보수 원가가
라이선스 수익을 잠식한다. 그래서 저작 도구는 부가 기능이 아니라 수익성의 전제다.

| 화면 | 하는 일 |
|------|---------|
| 컴플라이언스 룰 | 초안 편집 → **실제 필터 블록으로 즉시 테스트** → 배포 → 이력에서 되돌리기 |
| STT 사전 | 상품명·전문용어 등록 (범용 STT가 확실히 틀리는 고유명사 교정) |
| 검색 튜닝 | 질의를 넣어 Dense/Sparse/리랭킹 **점수 분해** 확인 — "왜 이 문서가 안 나오지"를 직접 진단 |
| 평가셋 | 골든셋으로 Recall@K·지연 측정 — 튜닝 전후 비교가 추측이 되지 않게 |
| 팝업 채택률 | 상담원이 실제로 썼는지 집계 + 개선 대상 질의 목록 |

`make up` 후 <http://localhost:8090/console>. 룰은 **초안 → 배포**를 명시적으로
거쳐야 반영되므로, 편집 중인 정규식이 상담 파이프라인에 새어 나가지 않는다.

### 품질 개선 루프가 실제로 닫혀 있다

```
저작 콘솔에서 상품명 사전 등록
   → 배포 채널(공유 저장소)로 발행
   → STT-CORE가 읽어 인식 교정 (무배담 행복플러스 → 무배당 행복플러스보험)
   → 상담원 워크스페이스에 교정된 자막 표시
   → 상담원이 팝업 "도움됨/아님" 클릭
   → 저작 콘솔 채택률 + 개선 대상 질의 목록에 반영
```

저작 블록과 실시간 블록은 **서로를 호출하지 않는다.** 저작 도구가 꺼져 있어도
마지막 배포본으로 상담이 계속 돈다 — 업무시간에만 콘솔을 켜 두는 고객사를 위해서다.

| 화면 | 주소 |
|------|------|
| 고객 데모 (마이크→자막) | `:8080/demo` |
| 상담원 워크스페이스 | `:8091/workspace` |
| 스마트 회의록 | `:8094/minutes` |
| 저작·학습 콘솔 | `:8090/console` |
| 라이선스 현황·설치 API | `:8095/docs` |
| 감사 조회·무결성 검증 API | `:8096/docs` |
| **운영 콘솔** | `:8097/console` |

### 라이선스는 폐쇄망에서 파일 두 개로 끝난다 (`CORE-LIC`)

고객사 망은 인터넷에 나가지 못한다. 온라인 활성화도, call-home도 쓸 수 없으므로
**파일 자체가 진위를 증명해야 한다.**

```
① 설치 서버   POST :8095/internal/v1/license/request   → acme.req (H/W 지문 해시)
② USB 반출    acme.req → 공급사 발급 서버
③ 발급 서버   licgen issue acme.req --key license_key.pem --expires 2027-12-31 \
                  --block STT-CORE:concurrent_channels=50 --catalog-root .
④ USB 반입    acme.lic → 설치 서버
⑤ 설치 서버   POST :8095/internal/v1/license           → 검증 후 원자적 설치
```

- **라이선스 서버를 두지 않는다.** 모든 블록이 같은 `.lic`을 읽어 각자 검증한다 —
  중앙 검증 서버는 폐쇄망에서 가장 피해야 할 단일 장애점이다
- **지문은 N-of-M 일치.** NIC 하나 교체했다고 서비스가 멈추면 정상적인 유지보수가
  장애가 된다. 부품별 해시를 남겨 2개 이상 일치하면 통과하되, 다른 서버로의 복제는 거부한다
- **만료는 30일 유예, 지문 불일치는 즉시 거부.** 갱신이 며칠 늦었다고 상담을 끊으면
  고객사 업무가 멈춘다. 반대로 복제 허용은 DRM의 존재 이유를 없앤다
- **개인키는 이 레포 어디에도 없다.** 공개키만 릴리스 빌드가 내장한다
- `CORE-LIC`만 라이선스 없이 뜬다 — 설치기가 라이선스를 요구하면 최초 구축에서
  아무도 설치할 수 없다

업셀은 `.lic` 재발급으로 끝난다. 채널 수를 50→100으로 올리는 데 재설치가 필요 없다.

### 감사 로그는 지울 수 없어야 증거가 된다 (`CORE-SEC`)

금융·공공 조달에서 감사 로그는 통과 조건이고, 그 가치는 "변조되지 않았음을
증명할 수 있는가"에서 나온다. 지울 수 있는 로그는 증거로 쓰이지 못한다.

각 레코드가 앞 레코드의 해시를 품는다. 한 줄을 고치거나 지우면 그 뒤 모든 해시가
어긋나고, 검증 API가 **몇 번째 레코드에서** 끊겼는지까지 짚어 준다.

```
GET :8096/internal/v1/audit/verify
→ {"intact": false, "broken_at": 3,
   "reason": "레코드 내용이 자기 해시와 맞지 않는다 — 이 레코드가 변조됐다"}
```

기록 경로가 둘인 이유:

| 경로 | 쓰는 곳 | 왜 |
|------|---------|-----|
| `audit.log` 토픽 (비동기) | 세션 시작·종료, 문서 파기, 룰 배포 | 감사 저장소가 밀려도 상담은 계속 돈다 |
| `POST /internal/v1/audit` (동기) | PII 원문 열람, 녹취 반출 | **기록 성공 후** 열람을 허용해야 한다. 열람은 됐는데 기록은 실패한 상태가 남으면 감사에서 그 열람은 없었던 일이 된다 |

저장 암호화는 **봉투 방식**이다. 레코드마다 임의의 DEK로 본문을 암호화하고 DEK만
마스터 키로 감싼다 — 키 교체 시 DEK만 다시 감싸면 되므로 수백 GB의 녹취를
재암호화하지 않는다. 전체 재암호화를 요구하는 설계는 폐쇄망에서 사실상 교체 불가다.

암복호는 각 블록이 인프로세스로 한다(`vai_common.crypto`). CORE-SEC의 API로
제공하면 저장 경로마다 네트워크 왕복이 붙고, 이 블록이 전 블록의 병목이자
단일 장애점이 된다.

> **한계를 분명히 한다.** 해시 체인은 변조를 *막지* 않고 *탐지*한다. root 권한자는
> 파일 전체를 다시 쓸 수 있다. 완전한 방어는 head 해시를 외부에 정기 공증하는
> 운영 절차와 함께여야 성립한다. KCMVP 검증모듈은 고객사 조달품이므로 어댑터
> 연동 지점만 제공하며, **제공자 미지정 시 조용히 AES로 폴백하지 않는다.**

### 운영 콘솔은 편의 기능이 아니라 원가 구조다 (`CORE-ADM`)

폐쇄망에서는 공급사가 원격으로 들여다볼 수 없다. 고객사 운영자가 스스로
"어느 블록이 죽었는지, 라이선스가 언제 만료되는지, 감사 로그가 온전한지"를
확인하지 못하면 모든 확인이 **출동**으로 이어지고, 출동 원가가 유지보수 수익을
잠식한다. 그래서 이 화면은 매출이 아니라 원가 쪽 항목이다.

`make up` 후 <http://localhost:8097/console>.

| 첫 화면이 즉시 알려 주는 것 | 왜 |
|---|---|
| 정상 블록 수 / 전체 | 죽은 블록을 한눈에. **응답 없음(unknown)과 죽음(down)을 구분한다** — 방화벽 문제를 블록 장애로 오인하면 조사 방향이 통째로 어긋난다 |
| 라이선스 만료 잔여일 | 30일 이내면 배너. 만료는 예고 없이 오면 사고, 미리 보이면 그냥 갱신 업무다 |
| 서명 검증 여부 | **꺼져 있으면 빨간 배너.** 서명 검증 없이 도는 빌드가 납품되는 것이 라이선스 사고의 대표 경로다 |
| 감사 무결성 + 끊긴 지점 | 감사 대응의 첫 화면 |
| 저장 암호화 활성 여부 | 제안서에는 있는데 현장에서는 꺼져 있는 상태를 잡아낸다 |

설계에서 지킨 것:

- **모든 블록을 동시에, 2초 상한으로 찌른다.** 순차로 돌면 죽은 블록마다 타임아웃이
  쌓여 화면이 멈춘다 — 장애 상황에서 가장 느려지는 화면이 장애 확인용 화면이면
  없는 것만 못하다
- **일부 조회가 실패해도 나머지는 그린다.** CORE-LIC이 죽었다고 블록 상태 표까지
  사라지면 운영자는 아무 단서도 못 얻는다
- **집계만 하고 저장하지 않는다.** 콘솔이 상태를 따로 저장하면 곧 원본과 갈라져
  "화면은 정상인데 실제로는 죽어 있는" 상태가 된다
- **인증은 게이트웨이와 같은 검증기를 쓴다**(`vai_common.auth`). 콘솔이 자체 인증을
  따로 두면 스코프 해석이 갈라지고, 게이트웨이에서 막힌 권한이 콘솔에서는 통과한다.
  상담원 토큰(`session:create`)으로는 들어올 수 없다
- **기본 비밀키로는 기동을 거부한다.** "나중에 바꾸겠다"로 남는 기본값이 이 영역의
  가장 흔한 취약점이다. 데모는 `VAI_ADM_REQUIRE_AUTH=false`로 **명시적으로** 끈다 —
  껐다는 사실이 설정에 남는 편이 낫다
- **거부된 접근과 감사 열람 자체가 감사에 남는다.** 성공만 남기면 침해 시도가
  보이지 않고, 감사 기록을 훑어 본 사실이 흔적 없이 사라진다

### 반입 목록은 사람이 만들지 않는다 (에어갭 번들)

폐쇄망 반입은 되돌릴 수 없다. USB를 들고 들어간 뒤 "이미지 하나가 빠졌다"를
알게 되면 반출입 승인을 다시 밟아야 하고, 고객사에 따라 며칠이 걸린다.
그래서 담을 목록을 **라이선스와 카탈로그에서 계산한다.**

```bash
make bundle-plan LICENSE=customer.lic     # 무엇이 담기는지 먼저 확인
make bundle      LICENSE=customer.lic     # dist/visionai-0.1.0.tar.gz
```

계산이 잡아 주는 것 — 전부 손으로 세면 빠지는 것들:

| 규칙 | 예 |
|---|---|
| **의존의 의존**까지 폐포 | `UI-AGENT` 하나 → 12블록. 직접 의존은 보이지만 의존의 의존은 안 보인다 |
| **이벤트 생산자** (생산자가 하나뿐일 때) | `UI-MEET`는 `speaker.label`을 소비한다 → `SPK-DIA`가 없으면 화자 라벨이 영원히 안 붙는다. `depends_on`에는 안 나타난다 |
| **기능 의존**(`recommends`) | `UI-AGENT`는 `TA-ASSIST` 없이도 뜬다 — 자막은 나오고 **지식 팝업 패널만 죽는다.** 담되 "라이선스 범위 밖"으로 따로 보고한다 |
| **인프라 이미지** | 검색 블록이 있으면 qdrant, 버스를 쓰면 redis. compose와 같은 태그를 쓰는지 테스트가 강제한다 |
| **CORE-LIC은 무조건** | 라이선스를 설치하는 블록이 번들에 없으면 최초 구축에서 아무것도 기동 못 한다 |

생산자가 여럿인 토픽(`audit.log`)은 **자동으로 다 담지 않는다.** 전부 담으면
라이선스 범위 밖 이미지가 무더기로 들어가므로, 하나도 안 담겼을 때만 경고한다.

설치기는 순서를 고정한다 — 앞 단계가 실패하면 뒤를 시작하지 않는다:

```
사전 점검(docker·디스크·포트·구성파일) → 무결성 대조(SHA256) → 적재 → 기동 → 자가진단
```

`./install.sh --dry-run`은 docker를 건드리지 않고 점검만 한다 — **반입 전에**
빌드 서버에서 돌려 볼 수 있다. 체크섬이 어긋나면 적재를 시작하지 않는다:
반쯤 깨진 이미지를 로드하고 원인 모를 장애를 쫓는 것이 최악이다.

재설치(업그레이드)에서는 우리 자신이 포트를 쓰고 있으므로, 기존 설치를 감지하면
포트 충돌을 실패가 아니라 업그레이드로 본다 — 폐쇄망에서 업그레이드는 재설치가
유일한 수단이라 이 경로가 막히면 치명적이다.

자가진단은 실패마다 **어디를 보라고** 알려 준다. 실패 목록만 던지는 진단은
결국 공급사 전화로 이어진다.

### 약관은 평문으로 오지 않는다 (문서 파서)

공공은 HWP, 금융은 PDF/DOCX다. **HWP를 못 읽으면 공공 조달 입찰 자체가 막힌다** —
"약관 파일을 넣어 보세요"라는 PoC 첫 단계에서 끝난다.

```bash
curl -F file=@약관.hwp -F tenant_id=acme :8086/internal/v1/kb/card/documents/upload
```

| 형식 | 방식 | 비고 |
|---|---|---|
| HWP 5.0 | CFB 컨테이너 → raw deflate → 레코드 파싱 | **제어 문자 폭**을 정확히 건너뛰는 것이 전부다. 확장 컨트롤은 16바이트인데 한 글자로 세면 그 뒤 텍스트가 통째로 깨져 그 문서는 검색에서 영원히 안 나온다 |
| HWPX·DOCX | zip + XML (**표준 라이브러리만**) | 에어갭 반입에서 의존성 하나는 검토 대상 하나다. 네임스페이스가 아니라 지역명으로 태그를 찾아 한글·워드 버전에 묶이지 않는다 |
| PDF | pypdf 텍스트 레이어 | |
| 평문 | UTF-8 → **CP949** → EUC-KR 순 | 국내 문서는 CP949 저장이 아직 많다. UTF-8만 시도하면 멀쩡한 약관이 "읽을 수 없음"이 된다 |

**실패를 성공으로 위장하지 않는다.** 빈 텍스트로 색인이 "성공"하면 고객사는
약관을 넣었는데 검색이 안 되는 이유를 영영 모릅니다. 그래서 400으로 즉시 알립니다:

- 스캔 PDF → `"텍스트 레이어가 없다 — OCR을 거친 사본이 필요하다"`
- 배포용 HWP → `"복호화 키가 필요해 읽을 수 없다. 원본 문서를 요청한다"`
- 암호 걸린 문서 → `"암호를 푼 사본이 필요하다"`

온전히 읽지 못한 부분은 문서에 경고로 남깁니다(표 안의 글자, 이미지 페이지,
머리말). 조용히 넘기면 "왜 이 조항만 검색이 안 되지"를 아무도 설명하지 못합니다.

확장자가 틀려도 **매직 바이트로 판별**합니다 — 고객사 파일은 확장자가 자주
틀리고(HWPX를 .hwp로 저장), 그 반려를 고객사는 제품 결함으로 봅니다.

### 산 만큼만 쓴다 (동시 채널 한도 강제)

`.lic`에 채널 수를 적어 놓고 아무도 세지 않으면 그 숫자는 장식입니다.
CORE-BUS가 세션 인입 시점에 셉니다.

```
#1~#3 → 201    #4 → 429  "동시 채널 한도(3)에 도달했다 — TA-ASSIST 라이선스 기준"
```

- **가장 빡빡한 블록이 상한을 정합니다.** TA-ASSIST를 50채널만 샀는데 STT를
  100채널 샀다고 100건을 받으면 51번째부터 **팝업 없는 상담**이 됩니다.
  계약과 동작이 어긋나는 쪽이 훨씬 나쁩니다.
- **어느 블록이 막았는지 응답에 담습니다.** 운영자가 "왜 통화가 안 받아졌나"를
  물었을 때 답이 있어야 증설 견적으로 이어집니다.
- **거부는 로그가 아니라 감사에 남습니다.** 놓친 상담은 매출이고, 매출 손실이
  로그 파일에만 있으면 아무도 못 봅니다.
- **TTL을 넘긴 세션은 걷어냅니다.** 종료 이벤트를 놓친 세션이 채널을 계속 잡으면
  한도가 조금씩 새어 나가고, 결국 라이선스 안에서 상담을 못 받는 상태가 됩니다 —
  원인을 찾기 가장 어려운 종류의 장애입니다.

콘솔은 사용률 70%에서 노랑, 90%에서 빨간 배너를 띄웁니다. 상한에 부딪힌 뒤에
아는 것은 이미 상담을 놓친 뒤입니다.

### 두 개의 제품 패키지가 같은 코어를 쓴다

```
                      ┌→ [AICC]    FLT-MICRO → TA-ASSIST → UI-AGENT
전화/마이크 → VAD → STT ┤
                      └→ [회의록]  SPK-DIA → UI-MEET
                                    ↘ 공통: LLM-SUM(요약)
```

프로파일(`AICC`/`MEETING`)이 세션 생성 시 정해져 파이프라인 전체로 전파된다.
화자분리는 회의 프로파일에서만 돌아 AICC에서 GPU를 낭비하지 않는다 —
상담은 채널(고객/상담원)로 이미 화자가 갈려 있기 때문이다.

```bash
make install          # uv 워크스페이스 동기화
make check            # 린트 · 블록 경계 · 타입 · 테스트 · 카탈로그 검증
make up && make demo  # compose 기동 → http://localhost:8080/demo
```

테스트는 **GPU도 Redis도 없이** 파이프라인 전체를 검증한다(인메모리 버스 + fake/hashing 어댑터).
Redis가 있으면 블록들을 실제 프로세스로 띄우는 스택 스모크 테스트까지 함께 돈다.

레고블록 원칙은 문서상의 약속이 아니라 CI 게이트다 — `import-linter`가 블록 간 직접
import, 계층 역전, 서비스 로직의 엔진 직접 참조, 상담 경로에서의 외부 SDK 사용을
차단하고, `blockctl check`가 매니페스트·의존·토픽 생산자·청구 단위 정합성을 검사한다.
