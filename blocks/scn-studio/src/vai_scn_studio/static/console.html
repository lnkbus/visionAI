검색 튜닝 콘솔

"왜 이 문서가 안 나오지"를 직접 진단한다. Dense(의미)·Sparse(키워드)·리랭킹 중 어디서 밀렸는지가 개선 방향을 정한다.

평가셋 실행

룰·사전·청킹을 바꾼 뒤 좋아졌는지 나빠졌는지를 숫자로 확인하지 못하면 모든 튜닝이 추측이 된다.

팝업 채택률

상담원이 팝업을 실제로 썼는지가 품질 개선의 유일한 객관 신호다. 채택되지 않은 질의가 곧 다음 개선 대상이다.

생애주기 — 초안 → 검증 → 시연 → 운영

한 칸씩만 올라간다. 편집 직후 운영으로 가는 지름길을 열면 결국 그 길로만 다니게 되고, 그러면 검증과 시연은 형식이 된다. 그리고 편집하면 초안으로 내려간다 — 검증을 통과한 뒤 한 글자만 고쳐도 그것은 더 이상 검증된 물건이 아니다.

시나리오 (JSON)

반출본에는 단계가 실리지 않는다. 다른 환경에 들여온 시나리오가 “운영”으로 표시되면 검증 없이 배포로 이어진다 — 반입본은 언제나 초안에서 시작한다.

흐름 복제

복제한 노드들 안쪽으로 향하는 연결만 새 이름으로 바뀐다. 바깥으로 나가는 연결은 그대로 두어 복제본이 기존 종료·연결 지점을 공유한다.

학습 도구 — 인텐트 일괄 편집

엑셀이 그대로 여는 CSV다. .xlsx를 쓰려면 라이브러리가 하나 더 필요하고 폐쇄망 반입 목록이 그만큼 길어지는데, 얻는 것은 셀 서식뿐이다. 표 편집으로 노드가 새로 생기지는 않는다 — 오타 하나로 아무 데도 연결되지 않은 노드가 만들어지는 것을 막는다.

운영 콘솔의 재학습 후보에서 내려받은 폴백 발화를 여기 examples 열에 | 로 이어 붙이면 그대로 반영된다.

배포 이력

불러오기를 누르면 표시된다.

되돌리기는 초안으로 복구한다. 되돌리는 것도 배포이므로 같은 검증을 거쳐야 하고, 그 사이에 바뀐 다른 것과 맞는지 확인할 기회가 필요하다.

대화 시뮬레이터 — 배포 없이 흐름 확인

고객사가 시나리오를 직접 늘리려면 “이렇게 말하면 어디로 가는지”를 스스로 볼 수 있어야 한다. 그게 안 되면 결국 공급사에 물어보게 된다. 실제 대화 엔진(BOT-VOICE)을 그대로 부른다 — 시뮬레이터 전용 구현을 두면 “시뮬레이터에서는 되는데 실제로는 안 된다”가 가능해진다.

읽기 미리듣기 — 숫자·금액·전문용어

합성 전에 읽기 텍스트를 본다. 소리를 들어야만 알 수 있으면 사전을 고칠 때마다 전체 합성을 돌려야 한다. “2,000원”이 어떻게 읽히는지, 상품명이 영어로 새는지가 여기서 드러난다.

읽기 사전 — 고유명사·사내 용어

전처리 규칙은 숫자·날짜·단위처럼 규칙으로 정해지는 것만 다룬다. “무배당행복플러스”를 어떻게 읽을지는 규칙이 없고 그 회사만 안다 — 그걸 코드로 받으면 안내 문구 하나에 공급사 배포가 필요해진다.

표기읽기 (한글)메모

읽기는 한글로 적는다. 숫자나 영문을 남기면 전처리 규칙이 다시 손대고 결과가 예측 불가능해진다. 띄어쓰기는 흡수하므로 “무배당행복플러스”와 “무배당 행복 플러스”를 따로 등록할 필요가 없다.

긴 표기부터 적용된다. 짧은 것이 먼저 걸리면 “행복플러스”가 이겨 “무배당행복플러스”를 등록한 의미가 사라진다.

저장하면 바로 배포된다. 룰셋과 달리 초안 단계가 없다 — 읽기가 틀리면 즉시 들리고 즉시 되돌릴 수 있어서, 배포 절차를 두면 얻는 것보다 잃는 것이 많다.
