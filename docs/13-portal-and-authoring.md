# 13. 운영 포털과 시나리오 저작

> 화면 이야기다. 무엇이 어디에 있고, 각 숫자가 **무엇을 세고 있는지**.
> 지표를 잘못 읽으면 그걸 근거로 증설하고 제안서에 적게 된다.

## 1. 화면 지도

| 화면 | 주소 | 누가 쓰나 |
|---|---|---|
| 운영 콘솔 | <http://localhost:8097/console> | 고객사 운영자 |
| 저작 콘솔 | <http://localhost:8090/console> | 고객사 시나리오 담당 |
| 상담원 워크스페이스 | <http://localhost:8091/workspace> | 상담사 |
| 스마트 회의록 | <http://localhost:8094/minutes> | 회의 참석자 |
| 고객 데모(마이크→자막) | <http://localhost:8080/demo> | 시연용 |

> 포트는 `deploy/compose/docker-compose.yml` 이 기준이다. 문서에 손으로 적은
> 번호는 언젠가 어긋나므로, 안 맞으면 `docker compose ps` 를 먼저 본다.

**뒤 경로는 외울 필요 없다.** `localhost:8097` 처럼 포트만 쳐도 그 블록의
화면으로 넘어간다. 화면이 없는 블록(STT-CORE 같은 API 블록)은 자기가
무엇이고 어디를 보면 되는지 알려 준다.

**운영 콘솔 6탭** — 플랫폼 상태 · 서비스 통계 · 콜 이력 · 재학습 후보 · 감사 로그 · 블록 시험
**저작 콘솔 8탭** — 컴플라이언스 룰 · STT 사전 · 검색 튜닝 · 평가셋 · 팝업 채택률 ·
시나리오 · 대화 시뮬레이터 · 읽기 미리듣기(+읽기 사전)

## 2. 서비스 통계 — 무엇을 세는가

수집은 CORE-ADM이 하되 **실시간 경로 밖**에서 돈다. 통계 저장이 느려도 상담은
그대로 돌아야 한다.

| 지표 | 어디서 | 정의 |
|---|---|---|
| 세션 | `session.closed` | 프로파일별(회의/상담)로도 나눈다 |
| 발화 | `filter.clean` | **확정분만.** 중간 인식을 세면 같은 말이 여러 번 잡힌다 |
| 인식 신뢰도 | `stt.delta` | 확정분 평균. `filter.clean`에는 신뢰도가 없다 |
| 개인정보 마스킹 | `filter.clean` | **0이 계속되면 마스킹이 꺼진 것을 의심한다** |
| 룰 적중 | `filter.clean` | 룰별 랭킹도 함께 |
| 사람 연결 비율 | `bot.turn` | 봇 턴 대비 handoff |
| 요약 성공률 | `summary.done` | 분모는 **끝난 건**(성공+실패) |
| 인식 양보 포기 | `summary.done` | 커지면 장비가 모자란다(docs/12 §4.1) |

### 평균을 두 번 내지 않는다

집계는 **합계와 개수를 따로** 담는다. 평균만 저장하면 기간을 합칠 때
평균의 평균이 되고, 그 값은 통화 수가 다른 날들 사이에서 틀린다.

```
1일: 100통, 평균 0.90     2일: 1통, 평균 0.50
  올바름: (90.0 + 0.5) / 101 = 0.896
  틀림:   (0.90 + 0.50) / 2  = 0.700
```

CORE-ADM 화면과 API가 모두 앞의 방식을 쓴다. 회귀 시험이 이 계산을 지킨다
(`blocks/core-adm/tests/test_analytics.py`).

### 보관

하루+테넌트 단위, 기본 90일 TTL(`VAI_ADM_ANALYTICS_RETENTION_DAYS`).
TTL의 이유는 용량이 아니라 **개인정보**다. 수집 자체를 끄려면
`VAI_ADM_ANALYTICS=false` — 끄면 실제로 저장하지 않는다.

## 3. 콜 이력

건별 대화 내용을 조회한다. 세 가지가 중요하다.

1. **마스킹본만 담긴다.** `filter.clean` 산출물이므로 원문은 어디에도 없다.
   이력 조회 화면은 개인정보 열람 창구가 되기 가장 쉬운 자리다.
2. **열람과 파기가 감사에 남는다.** `call.view` / `call.delete` 로 남기며,
   실제 원문 열람(`pii.reveal`)과 이름을 나눈다 — 같은 이름이면 진짜 원문
   열람이 일상 조회에 묻힌다.
3. **잘렸으면 잘렸다고 적는다.** 발화 500건이 상한이고, 넘으면 기록에
   `truncated` 가 선다. 숨기면 이력을 증거로 쓸 수 없다.

발화가 하나도 없던 세션(오접속·즉시 끊김)은 이력에 남기지 않는다 — 세션 수는
세되 목록은 깨끗해야 조회가 쓸모 있다.

## 4. 재학습 후보 → 학습 도구

```
봇이 사람에게 넘김(bot.turn handed_off)
        ↓  직전 고객 발화를 모은다
운영 콘솔 [재학습 후보]  ──CSV──▶  저작 콘솔 [학습 도구]
                                    examples 열에 | 로 이어 붙인다
```

무엇을 물었는데 못 알아들었는지가 인텐트 보강의 **유일한 1차 자료**다. 이것
없이 인텐트를 늘리는 것은 추측이고, 추측으로 늘린 정규식은 대개 다른 갈래를
망가뜨린다. 반복 횟수가 높은 것부터 손대는 것이 가장 싸다.

> CSV를 쓰는 이유: 엑셀이 그대로 연다. `.xlsx` 를 만들려면 라이브러리가 하나
> 더 필요하고 폐쇄망 반입 목록이 그만큼 길어지는데, 얻는 것은 셀 서식뿐이다.
> BOM은 붙인다 — 없으면 한글이 깨져서 열리고, 한 번 깨져 본 사람은 그 도구를
> 다시 쓰지 않는다.

## 5. 시나리오 생애주기

```
초안 ──검증──▶ 검증 통과 ──시연──▶ 시연 확인 ──배포──▶ 운영
 ▲                                                      │
 └──────────── 편집하면 언제든 초안으로 ────────────────┘
```

| 단계 | 무슨 일이 실제로 일어나나 |
|---|---|
| DRAFT | 편집 중 |
| BUILT | **BOT-VOICE의 실제 검증기**를 부른다. 저작 콘솔이 자체 검증을 두면 "여기선 통과인데 배포에서 거부"가 생긴다 |
| STAGING | 시뮬레이터로 확인했다는 표시. 구조가 맞는 것과 말이 되는 것은 다르다 |
| LIVE | **BOT-VOICE에 실제로 배포**하고 직전 판을 이력에 남긴다 |

세 가지 규칙:

1. **한 칸씩만 올라간다.** 지름길을 열면 결국 모두가 그 길로 다니고, 검증과
   시연은 형식이 된다.
2. **편집하면 초안으로 내려간다.** 검증을 통과한 뒤 한 글자만 고쳐도 그것은
   더 이상 검증된 물건이 아니다. 이 한 줄이 없으면 생애주기는 장식이다.
3. **되돌리기도 초안으로 복구한다.** 되돌리는 것도 배포이므로 같은 검증을
   거쳐야 하고, 그 사이 바뀐 다른 것과 맞는지 볼 기회가 필요하다.

### 반출입

반출본에는 **단계가 실리지 않는다.** 다른 환경에 들여온 시나리오가 "운영"으로
표시되면 검증 없이 배포로 이어진다. 반입할 때 테넌트는 **받는 쪽 것으로
덮어쓴다** — 꾸러미 안 테넌트를 믿으면 파일 하나로 남의 영역에 쓰기가 일어난다.

### 흐름 복제

복제한 노드들 **안쪽 연결만** 새 이름으로 바꾼다. 바깥으로 나가는 연결은 그대로
두어야 복제본이 기존 종료·연결 지점을 공유한다. 전부 바꾸면 복제본이 자기만의
막다른 골목을 갖게 된다.

## 6. 읽기 사전 — 규칙이 없는 말

전처리 규칙은 숫자·날짜·단위처럼 **규칙으로 정해지는 것**을 다룬다.
"무배당행복플러스"를 어떻게 읽을지는 규칙이 없고 그 회사만 안다. 그걸 코드로
받으면 안내 문구 하나에 공급사 배포가 필요해진다.

```
저작 콘솔 [읽기 미리듣기 ▸ 읽기 사전]
        │ 저장하면 즉시 배포 채널로
        ▼
TTS-CORE  합성 직전, 숫자·단위 규칙보다 **먼저** 적용
```

| 규칙 | 왜 |
|---|---|
| 읽기는 **한글로** 적는다 | 숫자·영문을 남기면 전처리 규칙이 다시 손대고 결과가 예측 불가능해진다 |
| **한 번만 훑는다** | 항목마다 따로 치환하면 앞서 바꾼 자리를 뒤 항목이 다시 건드린다 |
| **긴 표기가 이긴다** | "행복플러스"가 먼저 걸리면 "무배당행복플러스"를 등록한 의미가 없다 |
| 띄어쓰기는 흡수한다 | 문서마다 붙여 쓰고 띄어 쓰는 것이 섞인다. 따로 등록하게 하면 한쪽은 반드시 빠뜨린다 |
| 상한 500건, 넘으면 **경고** | 조용히 자르면 등록했는데 왜 안 읽히는지 알 수 없다 |

**초안 단계를 두지 않는다.** 룰셋과 달리 읽기가 틀리면 즉시 들리고 즉시 되돌릴
수 있다 — 배포 절차를 두면 얻는 것보다 잃는 것이 많다.

미리듣기 결과에 **적용된 사전 항목 수**를 함께 적는다. 0이면 규칙만 돈 것이고,
"등록했는데 안 읽힌다"와 "애초에 사전이 없다"를 화면이 구분해 준다.

STT 사전과 나눠 둔 이유는 **방향이 반대**라서다. STT는 '잘못 들린 것을 정답
표기로', TTS는 '쓰인 표기를 어떻게 소리 낼지'다. 하나로 합치면 한쪽을 고칠 때
다른 쪽이 조용히 망가진다.

## 7. 아직 없는 것

| | 왜 안 했나 |
|---|---|
| 도형 시나리오 편집기 | JSON 편집으로 기능은 된다. 제안 평가용으로는 필요하다 |
| 합성 소리 듣기 | `tts/synthesize`(WAV)는 있으나 저작 화면이 아직 재생하지 않는다 |
| 예약 배포 | 즉시 배포만 있다. 스케줄러가 새 상태 저장소를 요구한다 |
| Entity · Webhook 관리 | 대화 엔진에 개념 자체가 없다 — 화면이 아니라 엔진 작업이다 |
| 인텐트 단위 랭킹 | 지금은 **노드** 랭킹이다. 인텐트 매칭 이벤트가 없어서다 |
| 모델 학습(Adaptation) | 학습 파이프라인이 없다. 다음 물결이다 |
