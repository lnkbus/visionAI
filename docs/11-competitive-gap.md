# 11. 경쟁 제안서 대비 격차 — 무엇이 없고, 무엇이 더 있는가

> 참고자료: **에스원 AICC 상담자동화 솔루션 구축 제안서** (03. 제안 내용, 16면)
> 이 문서는 그 제안서의 항목을 우리 제품에 하나씩 대 본 결과다.
> **없는 것을 없다고 적는 것이 목적**이다 — 제안서 대응 시 여기가 그대로 리스크다.

## 요약

| | 최초 점검 | 지금 |
|---|---|---|
| ✅ 대응됨 | 3 | **11** |
| ◐ 부분 (API는 있고 화면이 없거나, 반대) | 9 | 11 |
| ✗ 없음 | 14 | 4 |

> 아래 표들의 실제 행을 센 값이다(총 26항목). 최초 작성 때 적었던 6·7·8은
> 합이 21로 항목 수와 맞지 않았다 — 세어서 고쳤다.

최초 점검에서 **가장 큰 격차는 "화면"이었다.** 엔진과 API는 상당 부분 있는데
경쟁 제안서가 그림으로 보여 주는 저작·운영 화면이 대부분 없었고, 제안 평가에서
그건 기능 부재와 같은 취급을 받는다.

그 화면들을 붙였다 — 대화 시뮬레이터, 읽기 미리듣기, 시나리오 생애주기,
Export/Import, 흐름 복제, 학습 도구(CSV), 그리고 AI Portal에 해당하는
서비스 통계·콜 이력·랭킹·폴백 재학습.

**남은 격차는 화면이 아니라 기능이다** — 모델 학습 파이프라인, SIP 시그널링
어댑터, 성능 실측. 이 셋은 화면을 붙여 메울 수 있는 것이 아니다.

## 03-04. AI 엔진 — Bot Builder

| 제안서 항목 | 우리 | 상태 |
|---|---|---|
| GUI 시나리오 제작 (Flow/Page 구조 설계) | JSON 편집 + 검증. **도형 편집기는 없다** | ◐ |
| Script 미리듣기 | 저작 콘솔 **읽기 미리듣기** 탭 — 텍스트. 소리는 없다 | ◐ |
| 발화별 Barge-In 설정 | 턴 단위 끼어들기는 구현. **발화별 설정 UI 없음** | ◐ |
| Intents 관리 | 저작 콘솔 **학습 도구** — CSV 일괄 편집. Entity/Webhook은 없다 | ◐ |
| **시나리오 Life Cycle** (DRAFT→BUILT→STAGING→운영) | 구현. 한 칸씩만 승격, 편집하면 초안으로 | ✅ |
| 예약 배포 / 즉시 배포 | 즉시 배포만. 예약은 없다 | ✗ |
| 시나리오 Export / Import, Flow 단위 복제 | 셋 다 구현 | ✅ |
| **대화 시뮬레이터** (배포 전/후 테스트) | 저작 콘솔 탭. 최근 30건 이력은 없다 | ✅ |
| 학습 도구 (인텐트 Excel 일괄 업/다운로드) | CSV(엑셀 호환)로 구현 | ✅ |
| 자동 테스트 (TDD GREEN-RED, 결과 Excel) | `evalctl` + 저작 콘솔 **평가셋** 탭. Excel 없음 | ◐ |

> Life Cycle과 Export/Import는 "고객사가 자체적으로 시나리오를 늘려 간다"는
> 제안서의 핵심 논리를 떠받친다. 그래서 여기부터 채웠다.
>
> **승격은 표시가 아니라 동작이다** — BUILT는 BOT-VOICE의 실제 검증기를 부르고,
> LIVE는 실제로 배포한다. 단계만 바꾸고 아무 일도 안 하면 화면과 현실이
> 갈라지고, 그게 이 기능의 가장 나쁜 실패다.

> 적었던 날이 같은 무게가 되어 조용히 틀린다. 틀린 지표는 지표가 없는 것보다
> 나쁘다 — 없으면 아무도 안 쓰지만, 틀리면 그걸 근거로 증설하고 제안서에 적는다.

## 우리에게 있고 제안서에 없는 것

균형을 위해 적어 둔다. 제안 대응에서 차별화 논지가 될 자리다.

| 우리 | 왜 의미 있나 |
|---|---|
| **오프라인 DRM** (H/W 지문, 라이선스 서버 없음, call-home 없음) | 폐쇄망 조달에서 그대로 요구사항이다 |
| **해시 체인 감사 로그** — 변조 탐지 + 끊긴 지점 특정 | 금융권 감사 대응 |
| **블록 단위 판매** — 배포·라이선스·청구가 한 단위 | 단계적 도입과 견적 유연성 |
| **에어갭 반입 계산** (의존 폐포·토픽 생산자 자동) | "이미지 하나 빠져 반입 재승인"을 없앤다 |
| **형상 고정 + 시점 이력** | GS인증 변경 통제, "그때 뭘 납품했나" |
| **품질 회귀 게이트** (골든셋 6종, CER/WER 포함) | 모델을 바꿔도 품질이 조용히 나빠지지 않는다 |
| **블록 인터페이스 시험 콘솔** | `/readyz` 초록인데 못 도는 상태를 잡는다 |
| **개인정보 마스킹이 룰셋과 무관하게 항상 동작** | 룰 편집 실수로 마스킹이 꺼지지 않는다 |

## 다음에 무엇부터 하나

화면 격차는 대체로 메웠다. 남은 것은 **화면으로 못 메우는 것들**이고,
순서는 조달에서 배점이 큰 쪽부터다.

1. **성능 실측** — `blockctl capacity` 의 GPU당 채널 값은 아직 설계 가정이다.
   제안서 숫자의 근거가 없으면 규모 산정 전체가 흔들린다(docs/12 §6).
2. **SIP 시그널링 어댑터** — 제어 API는 열려 있으나 실제 교환기 연동이 없다.
   고객사 CTI마다 다르므로 첫 사이트에서 만들어야 한다.
3. **TTS 사전 편집 UI** — 전처리는 구현돼 있고 편집 화면만 없다. 싸다.
4. **도형 시나리오 편집기** — JSON 편집으로 기능은 되지만, 제안 평가에서
   그림은 그림으로만 대응된다.

**모델 학습(Adaptation / 전속 합성)** 은 파이프라인 자체가 없다. 이건 제품
로드맵의 다음 물결이지 화면 작업이 아니다 — 없다고 적고 가는 편이 낫다.
