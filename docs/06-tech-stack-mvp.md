### 알려진 제약

- **`memory` 벡터 저장소는 단일 프로세스 전용이다.** RAG-KB와 RAG-SRCH를 별도
  컨테이너로 띄우면 색인한 문서가 검색에 보이지 않는다. 다중 컨테이너 배포에는
  Qdrant를 쓴다(compose 기본값). 오설정 시 기동 로그에 경고가 남는다.
- **BM25 색인은 메모리 상주다.** 프로세스 재시작 시 `VAI_SRCH_WARM_TENANTS`
  또는 `/internal/v1/kb/{kb}/rebuild`로 복원해야 한다. 복원하지 않으면 검색이
  밀집 축만으로 도는 "절반만 동작하는" 상태가 되는데, 장애로 보이지 않아 더 위험하다.
- **한국어 토큰화는 어절 + 음절 바이그램**이다. 형태소 분석기(kiwi/mecab)는
  평가셋으로 이득을 측정한 뒤 어댑터로 교체한다.
- **추천 답변 생성은 아직 없다.** 팝업은 근거 원문을 그대로 보여준다 —
  없는 답을 지어내느니 원문이 낫다는 판단이며, sLLM 생성은 다음 스프린트다.
- **기본 화자 임베더(spectral)는 음역이 뚜렷이 다른 화자만 가른다.** 같은 성별의
  비슷한 목소리는 한 사람으로 뭉친다. 회의록 품질이 필요한 고객사는 반드시
  신경망 임베더(ECAPA-TDNN 계열)를 쓴다 — 어댑터 교체만으로 되지만
  **유사도 임계값을 재조정해야 한다**(임베더마다 유사도 분포가 다르다).
- **화자분리는 온라인 방식이라 후처리 재군집화가 없다.** 회의 초반에 갈린
  화자가 후반에 같은 사람으로 밝혀져도 되돌리지 않는다. 오프라인 배치
  재군집화(회의 종료 후 전체 재계산)는 정확도가 높지만 미구현이다.
- **SIP 시그널링은 구현하지 않았다.** 고객사마다 미디어를 받는 방식이 다르다
  (SIPREC 복제 / 미디어 게이트웨이 / CTI 이벤트). 어느 하나를 가정해 SIP UA를
  만들면 대부분의 고객사에서 못 쓰는 코드가 되므로, **제어 API**(`/internal/v1/calls`)를
  열어 두고 시그널링 어댑터는 구축 시 고객사 환경에 맞춰 붙인다.
- **RTCP는 처리하지 않는다.** 홀수 포트는 관례대로 비워 두지만 수신·해석은
  하지 않는다. 통화 품질 지표는 RTP 수신 통계로만 산출한다.
- **손실 은닉(PLC)이 없다.** 유실 구간은 무음으로 채운다. G.711에 PLC가 없어
  이게 표준적인 최소 처리이며, 손실률이 높은 망에서는 인식률이 떨어진다.
- **시나리오 흐름 저작은 미구현이다.** SCN-STUDIO는 현재 컴플라이언스 룰 저작만
  제공한다. 분기·조건·기간계 액션 호출을 담는 흐름 에디터와 시뮬레이터는
  BOT-VOICE(Wave 7)와 함께 설계해야 중복 없이 만들 수 있다.
- **Helm 차트는 렌더링까지만 검증된다.** 이 개발 환경에 K8s 클러스터가 없어
  실제 기동·프로브·볼륨 바인딩은 확인하지 못했다. K3s 단일노드 리허설이 남았고,
  그 전까지 `values.yaml`의 storageClass·accessMode는 고객사 환경에 맞춰야 한다.
- **Ingress·TLS는 껍데기만 있다.** 고객사마다 L7 구성(F5·NGINX·Apache)이 달라
  하나를 가정하면 대부분에서 못 쓴다. 구축 시 붙인다.
- **HWP 표 안의 글자는 추출되지 않는다.** 표 개체는 별도 레코드에 있어 본문
  레코드만 읽는 현재 구현으로는 안 잡힌다. 해당 문서에는 경고를 남긴다.
  표가 많은 약관은 HWPX로 받는 편이 낫다(표 내부까지 그대로 읽힌다).
- **배포용 HWP(ViewText)와 암호 문서는 읽지 못한다.** 복호화 키가 필요하므로
  원본을 요청하는 것 외에 방법이 없다 — 오류 메시지에 그렇게 적어 둔다.
- **스캔 PDF는 OCR이 없다.** 텍스트 레이어가 없으면 실패로 알린다.
  OCR 엔진은 폐쇄망 반입 대상이 하나 더 느는 일이라 고객사와 합의할 사항이다.
- **번들 빌드의 docker 경로는 CI에서만 검증된다.** `docker save`/`load`는 데몬이
  필요해 단위 테스트로 덮을 수 없다. 계획 계산·체크섬·사전 점검·무결성 대조는
  전부 테스트로 고정돼 있다.
- **`recommends`(기능 의존)는 아직 UI-AGENT→TA-ASSIST 하나뿐이다.** 다른 화면·
  블록의 기능 의존은 패키지 구성이 확정되는 대로 채운다.
- **운영 콘솔에 테넌트·사용자 관리 화면이 없다.** 현재는 조회 전용(블록 상태·
  라이선스·감사)이다. 권한 부여는 IdP/SSO 연동과 함께 설계해야 하므로 토큰 발급은
  아직 `issue_access_token`(개발용)에 머문다.
- **GPU 자원·세션 이력 위젯이 없다.** Prometheus 연동과 CORE-BUS 세션 이력 API
  확장이 선행돼야 한다.
- **해시 체인은 변조를 막지 않고 탐지한다.** root 권한자는 파일 전체를 다시 쓸 수
  있다. 완전한 방어는 head 해시를 외부에 정기 공증(일일 출력·별도 매체 보관)하는
  **운영 절차**와 함께여야 성립한다 — 기술만으로 닫히지 않는 부분이다.
- **CORE-SEC은 단일 인스턴스여야 한다.** 해시 체인은 단일 라이터를 전제한다.
  여러 인스턴스가 같은 디렉토리에 쓰면 체인이 깨진다. 감사 기록량이 한 프로세스를
  넘어서는 규모에서는 테넌트별 체인 분리가 필요하다(미구현).
- **KCMVP 검증모듈은 연동 지점만 있다.** 실제 모듈은 고객사 조달품이고 연동
  방식(PKCS#11/전용 SDK/HSM)이 벤더마다 다르다. 제공자 미지정 시 **조용히 AES로
  폴백하지 않고 오류를 낸다** — 검증모듈을 쓴다고 적어 놓고 소프트웨어 암호가
  도는 것이 이 영역에서 가장 나쁜 사고이기 때문이다.
- **감사 이벤트 생산자는 아직 세 곳이다.** CORE-BUS(세션 시작·종료),
  RAG-KB(문서 파기), SCN-STUDIO(룰 배포). 로그인·PII 원문 열람·녹취 반출은
  해당 화면이 생기는 시점(CORE-ADM)에 붙인다.
- **개발 체크아웃에서는 서명 검증이 꺼져 있다.** 공개키가 레포에 없기 때문이며,
  이 상태로 납품되면 DRM이 없는 것과 같다. 릴리스 빌드가 공개키를 내장해야 켜진다.
  CORE-LIC은 기동 시 경고를 남기고 `/internal/v1/license`의 `signature_verified`로 노출한다.
- **라이선스 폐기(revocation) 목록이 없다.** 폐쇄망은 폐기 목록을 받을 경로가
  없으므로, 계약 종료는 만료일로만 다룬다. 조기 회수가 필요하면 짧은 만료로 발급하고
  갱신하는 방식이 유일한 수단이다.
- **시간 단위 용량(`audio_hours_monthly`)은 아직 강제되지 않는다.** 동시 채널은
  CORE-BUS가 세지만, 월 누적 시간은 집계 저장소가 선행돼야 한다. 회의록 패키지를
  시간제로 파는 계약에서는 이 부분을 채워야 한다.
- **동시 채널은 CORE-BUS 단일 인스턴스를 전제한다.** Redis 정렬 집합으로 세므로
  여러 CORE-BUS가 같은 Redis를 보면 정확하지만, 세션 생성이 확인-후-등록이라
  극단적 동시 인입에서 한두 건이 상한을 넘을 수 있다. 채널 과금 특성상
  허용 오차로 두되, 엄밀함이 필요하면 Lua 스크립트로 원자화한다.
- **룰 배포는 산출물 생성까지다.** 배포 시 FLT-MICRO 형식 JSON을 만들어 주지만,
  필터 블록에 자동 반영되지는 않는다(현재는 파일 주입). API 배포는 Wave 6.

### 로컬 실행

```bash
make install          # uv 워크스페이스 동기화
make check            # 린트 + 블록 경계 + 타입 + 테스트 + 카탈로그 검증
make up && make demo  # compose 기동 후 http://localhost:8080/demo
```

`make test`는 Redis도 GPU도 요구하지 않는다(인메모리 버스 + fake 어댑터).
Redis가 떠 있으면 실프로세스 스택 스모크 테스트까지 함께 돈다.

### 블록 개발 규칙

1. **블록 간 코드 import 금지** — 공유는 `libs/` 아래 명시적으로 올린 것만 허용
   (`vai_contracts` 계약 · `vai_common` 런타임 인프라 · `vai_retrieval` 검색 인프라). CI에서 import-linter로 강제
2. **계약 우선**: 이벤트 스키마(AsyncAPI)·API(OpenAPI)를 먼저 정의 → 코드 생성. 계약 변경은 하위 호환 검사 통과 필수
3. **어댑터 플러그인**: 엔진 추가는 `adapters/`에 클래스 추가 + entry-point 등록. 코어 수정 발생 시 설계 리뷰
4. **환경 분기 금지**: `if is_onprem:` 대신 어댑터/설정 주입
5. **블록 인수 기준(DoD)**: 계약 테스트 + 단독 기동 smoke + 성능 예산(해당 시 지연 목표) 통과 → 그 시점부터 견적·청구 가능한 상태로 간주
6. **fake 어댑터 필수**: 모든 AI 엔진 블록은 결정적 fake 구현 제공 — GPU 없는 CI에서 전체 파이프라인 통합 테스트

## 3. 핵심 인터페이스 (요약)

- 이벤트 버스 토픽: `audio.in` → `audio.segment` → `stt.delta` → `filter.clean` → `assist.popup` / `session.closed` → `summary.done`
  - **Stream**(Redis Streams, 컨슈머 그룹): 위 토픽들. 타입별 스트림 1개 + 메시지의 `session_id` 필드로 세션 구분 — 세션마다 스트림을 만들면 워커가 신규 세션을 발견할 방법이 없다
  - **UI 채널**(Redis Pub/Sub): `vai:ui:{session_id}`. 접속 중인 화면으로의 팬아웃 전용 — 내구성이 불필요하고 UI 렌더 예산(<50ms)에 유리
- WebSocket `/v1/audio/stream` 프로토콜: [02 문서](02-architecture.md) §4 (사양서 원문 규격 준수)
- REST(관리): `/v1/kb/*`(지식), `/v1/sessions/*`(이력), `/v1/admin/*`(테넌트·룰셋·라이선스 상태), `/v1/rules/*`(컴플라이언스 룰셋 CRUD)

### MVP 데모 시나리오 (Wave 4 종료 시)

> 전화 시뮬레이터로 상담 통화 재생 → 상담원 화면에 실시간 자막(고객/상담원 채널 분리) →
> 주민번호 발화 시 즉시 마스킹 표시 → "결제일 연기 되나요?" 발화 1초 내 약관 팝업+추천 답변 →
> 통화 종료 수 초 후 카테고리·표준 요약 자동 생성 → 어드민에서 GPU 사용률·지연 대시보드 확인

## 6. 다음 스프린트 백로그 (Wave 6 — 패키징)

AICC와 회의록 두 패키지가 모두 동작한다. 남은 것은 **고객사에 인도 가능한
형태로 만드는 일**이다 — 지금은 개발 환경에서만 돈다.

1. ~~`CORE-LIC` 정식 DRM~~ ✅ — 지문 수집·발급요청·서명 검증·설치까지 동작한다.
   남은 것은 릴리스 빌드가 공개키를 내장하는 단계(아래 6번과 함께)
2. ~~`CORE-SEC`~~ ✅ — 해시 체인 감사 로그와 봉투 암호화가 동작한다.
   남은 것은 실제 KCMVP 검증모듈 연동(고객사 조달품이라 사업별 구축 항목)
3. ~~`CORE-ADM` 운영 콘솔~~ ✅ — 블록 상태·라이선스·감사 무결성이 한 화면에 모인다.
   남은 것은 테넌트/사용자 관리와 GPU 자원·세션 이력 위젯(CORE-BUS 이력 API 확장 필요)
4. ~~에어갭 번들~~ ✅ — 반입 계획 계산·번들 빌드·설치기·자가진단이 동작한다.
