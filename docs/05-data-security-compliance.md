# 05. 데이터 · 보안 · 컴플라이언스

금융권 B2B에서 보안·컴플라이언스는 기능이 아니라 **입찰 자격**이다. 설계 단계부터 반영한다.

## 1. 규제 대응 맵

| 규제/기준 | 요구사항 요지 | 제품 대응 |
|-----------|---------------|-----------|
| 전자금융감독규정 (망분리) | 내부망과 인터넷망 분리, 외부 전송 통제 | 완전 에어갭 구성(외부 API 호출 0건), H/W Fingerprint 오프라인 라이선스(call-home 없음) |
| KCMVP (암호모듈 검증) | 공공·금융 암호화 요건 | KCMVP 검증모듈 적용 — ARIA-256/AES-256 저장·전송 암호화 |
| GS인증 (공공 조달) | 소프트웨어 품질 인증 | 회의록 패키지 GS인증 취득 → 나라장터 등록 (Wave 6) |
| 개인정보보호법 | 수집 최소화, 목적 제한, 파기, 위탁 관리 | 개인정보 자동 탐지·마스킹, 보존기한·파기 정책 엔진, 수탁사 문서 세트 |
| 신용정보법 | 신용정보 처리 제한, 접근 기록 | 접근 로그 3년 보존, 권한 분리(RBAC) |
| 금융권 클라우드 이용 가이드 | 중요도 평가, CSP 안전성 | SaaS 금융존 옵션, 국내 리전, 평가 대응 문서 |
| ISMS-P (링버스 자체) | SaaS 운영 조직 인증 | Y2 인증 취득 목표 — 인프라·정책 초기부터 정렬 |
| AI 관련 가이드(금융분야 AI 가이드라인 등) | 설명가능성, 인간 개입, 책임성 | pipeline_run 재현 가능 기록, 상담원 전환 상시 제공, 가드레일 |

## 2. 개인정보 처리 설계

### 2.1 데이터 흐름 원칙

```
고객 발화 → [PII 탐지기] → 원문(암호화 저장, 접근 통제) 
                          → 마스킹본(LLM 프롬프트·로그·분석용)
```

- **LLM에는 마스킹본만 전달하는 것을 기본값**으로 한다. 업무상 필요(본인확인 후 계약 조회 등)한 필드만 정책에 따라 선별 통과
- PII 탐지: 정규식(주민번호·카드번호·계좌·전화) + NER 모델(이름·주소) 이중
- SaaS에서 상용 LLM API 사용 시: 마스킹 + API 제공사의 무학습(no-training) 계약 조건 명시 — 고객사 보안 질의서 대응 근거

### 2.2 보존·파기

| 데이터 | 기본 보존 | 근거 |
|--------|-----------|------|
| 상담 대화 원문 | 테넌트 정책(기본 3년) | 분쟁 대응, 금융권 관행 |
| 음성/영상 녹취 | 테넌트 정책(기본 1~3년) | 완전판매 입증 등 |
| 감사 로그 | 3년+ | 접근기록 의무 |
| 임베딩/청크 | 원문서 삭제 시 연쇄 삭제 | 파기 완전성 |

- 파기는 스케줄러가 자동 실행하고 파기 이력을 남긴다(파기 증적)

## 3. 보안 아키텍처

| 영역 | 설계 |
|------|------|
| 인증 | OIDC 기반. 온프렘은 고객사 SSO(SAML/OIDC) 연동, 관리자 MFA 필수 |
| 인가 | RBAC: 시스템관리자/테넌트관리자/수퍼바이저/상담원/감사자(read-only) 역할 분리 |
| 전송 암호화 | 전 구간 TLS 1.2+, 내부 서비스 간 mTLS(온프렘 옵션) |
| 저장 암호화 | KCMVP 모듈(ARIA/AES-256): 오디오 원본·DB PII 필드·디스크 레벨. 테넌트별 키 분리(Enterprise) |
| 코드 보호 | 온프렘 릴리스는 Cython/C++ 컴파일(`.so`) + PyArmor 난독화 — 소스 유출 방지 |
| 비밀 관리 | K8s Secret + 외부 Vault 연동 옵션(고객사 KMS 수용) |
| 감사 로그 | append-only 저장, 위변조 방지(해시 체인), 관리자 행위 전수 기록 |
| 공급망 | 이미지 서명(cosign), SBOM 제공 — 온프렘 반입 보안성 검토 대응 |
| 취약점 관리 | 의존성 스캔 CI 게이트, 분기 모의해킹(정식 출시 후) |

## 4. AI 특유 리스크 통제

| 리스크 | 통제 |
|--------|------|
| 환각(잘못된 안내) | 근거 없는 답변 차단(인용 강제 모드), 확신도 낮으면 "확인 후 안내"로 전환, 금액·수치는 시나리오/API 경로로만 |
| 프롬프트 인젝션 | 지식베이스 문서를 데이터로 격리(시스템 지시와 분리), 입력 필터, 출력 가드레일 |
| 규제 위반 발화 | 금지 표현 사전(투자 권유·확정 수익 표현 등) 후처리 필터, 테넌트별 커스텀 |
| 편향/부적절 응대 | 응대 톤 정책 프롬프트 + 사후 샘플링 QA 대시보드 |
| 책임 소재 | 모든 응답의 pipeline_run 기록으로 재현, "AI 상담 고지" UX, 중요 거래는 인간 승인 단계 |

## 5. 고객사 보안심사 대응 패키지 (영업 자산)

온프레미스 영업에서 반복 요구되는 문서를 표준화해 사전 준비한다:

1. 보안 아키텍처 기술서 (본 문서 기반)
2. 개인정보 처리 흐름도 및 위탁 문서 세트
3. SBOM + 오픈소스 라이선스 고지서
4. 침투테스트 결과 요약(연 1회 갱신)
5. 데이터 반출입 절차서(에어갭 설치·진단 번들)
6. 사업연속성(BCP)·백업/복구 절차서
