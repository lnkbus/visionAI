# 03. 배포 전략 — 폐쇄망 온프레미스 / SaaS 하이브리드

## 1. 배포 형태 개요

| | SaaS | 온프레미스 (폐쇄망) |
|---|------|---------------------|
| 인프라 | 링버스 운영 K8s | 고객사 K8s (단일노드~소규모) / PoC는 Docker Compose |
| 네트워크 | 인터넷 | Air-Gapped — 외부 호출 0건 |
| AI 엔진 | 로컬 서빙 풀 또는 상용 API 어댑터 | 전부 로컬: Faster-Whisper/CosyVoice/vLLM/Qdrant |
| 라이선스 | 구독 DB + 미터링 | H/W Fingerprint 오프라인 DRM (`.lic`) |
| 업데이트 | 무중단 롤링(주 단위) | 분기 릴리스 번들, 고객 변경관리 절차 |
| 코드 보호 | — | Cython/C++ 컴파일(`.so`) + PyArmor 난독화 |
| 운영 주체 | 링버스 SRE | 고객사 운영팀 + 링버스 기술지원 |

**공통 원칙**: 동일 블록 이미지·동일 차트. 환경 차이는 values 오버레이와 어댑터 설정으로만 표현.

## 2. 패키징 구조 (블록 단위)

```
deploy/
├── charts/visionai/            # 우산(umbrella) 차트 — 블록 서브차트 조립
│   ├── values.yaml             # 공통 기본값
│   ├── values-saas.yaml        # SaaS 오버레이 (멀티테넌트, API Provider)
│   └── values-onprem.yaml      # 온프렘 오버레이 (로컬 엔진, 에어갭)
├── bundles/                    # 제품 패키지 = 블록 조립 정의
│   ├── aicc.yaml               # 패키지 A: 활성 블록 목록 + 프로파일
│   ├── meeting.yaml            # 패키지 B
│   └── avatar.yaml             # 패키지 C
├── airgap/
│   ├── build_bundle.sh         # bundle.yaml 기준 필요한 블록 이미지+모델만 tar.gz 패키징
│   ├── install.sh              # 내부 레지스트리 적재 → K8s/Helm 설치 → 라이선스 활성화
│   └── selftest/               # 설치 후 자가진단 (STT 왕복, 팝업 지연 측정 리포트)
└── compose/                    # PoC/데모용 docker-compose (GPU 1대)
```

- **번들은 블록 단위로 최소 구성**: 회의록 패키지 반입 시 AICC 전용 블록(AUD-RTP 등)은 포함되지 않음 → 반입 심사 대상 축소, 이미지 크기 절감
- 모델 가중치(STT/TTS/sLLM/임베딩/리랭커)는 GPU 프로파일별로 사전 선별해 번들에 포함

## 3. 온프레미스 설치 (에어갭)

### 3.1 설치 절차

1. **번들 생성** (링버스, 인터넷 환경): `build_bundle.sh <bundle> <gpu-profile>` → 블록 이미지 + 차트 + 모델 가중치 + 서명 해시를 단일 `.tar.gz`로
2. **반입**: 고객사 보안성 검토·매체 검사 절차 준수 (SBOM·이미지 서명 제공)
3. **설치**: `install.sh` — 내부 레지스트리 push → 고객사 K8s에 Helm 설치 → `.lic` 활성화 → 초기 관리자 계정
4. **자가진단**: 오디오 왕복 smoke test — STT 정확도 샘플, Assist 팝업 p95 지연, GPU 점유 리포트 출력 → 검수 문서로 활용

### 3.2 표준 사양 프로파일

| 프로파일 | 용도 | GPU | 구성 |
|----------|------|-----|------|
| **S** (PoC/소형) | AICC ~30ch 또는 회의실 5개 | L4/A10 1장 (STT+SLM 소형, sLLM 7B INT4) | 단일노드 K8s 또는 Compose |
| **M** (표준) | AICC ~100ch | A100/H100 1~2장 (sLLM 14B, Triton STT) | 앱 3노드 + GPU 1노드 + DB HA |
| **L** (대형) | AICC 300ch+ / 통합 패키지 | GPU 4장+ | 풀 HA, 블록별 GPU 풀 분리 |

### 3.3 업데이트

- 분기 릴리스 트레인(LTS 성격), 핫픽스는 보안/치명 결함 한정
- 블록 단위 부분 업데이트 지원: 변경된 블록 이미지만 반입 (블록 계약이 호환성 경계)
- DB 마이그레이션은 expand-contract(전방 호환), 버전 스킵(N-2→N) 지원

## 4. 오프라인 DRM 라이선스 (CORE-LIC)

```
[발급 절차]
1. 고객사 서버에서 fingerprint 수집기 실행
   → GPU UUID + CPU Serial + MAC Address → SHA-256 하이브리드 Fingerprint
2. 링버스 발급 서버에서 .lic 생성:
   { fingerprint, 만료일, 블록 플래그, 용량(동시 채널 수 등) } → RSA-4096 서명
3. 반입·설치. 기동 시 공개키 검증 → 메모리 상에서만 복호화 → 블록 게이팅 적용
```

| 항목 | 정책 |
|------|------|
| 검증 방식 | 완전 오프라인 — call-home 없음 (망분리 환경에서 외부 통신 시도는 감점 요인) |
| 게이팅 대상 | 블록 활성화 + 용량(동시 채널/시트/월 처리시간) — [00 카탈로그](00-module-catalog.md) §4.4 |
| H/W 교체 | 재발급 절차(구 fingerprint 폐기 확인서) — 유지보수 계약 내 무상 |
| 만료 처리 | 30일 유예 경고 → 신규 세션 제한. 기존 데이터 조회는 차단하지 않음 |
| 업셀 | `.lic` 재발급만으로 블록 개통 (+신규 블록이면 이미지 반입) |

## 5. 코드·데이터 보호

| 영역 | 방식 |
|------|------|
| 코드 보호 | 핵심 모듈 Cython/C++ 컴파일(`.so`) + PyArmor 난독화 — 소스 유출 방지 |
| 저장 암호화 | KCMVP 검증모듈 적용 ARIA-256/AES-256 (오디오 원본·대화 데이터) |
| 전송 암호화 | 전 구간 TLS 1.2+, 내부 mTLS 옵션 |
| 공급망 | 이미지 서명(cosign) + SBOM — 반입 보안성 검토 대응 |

## 6. SaaS 운영 구조

- 단일 국내 리전 시작 → 금융 고객용 "금융존" 클러스터 분리 옵션
- CI/CD: main → 스테이징 자동 → 프로덕션 승인 배포. 이미지 태그는 온프렘 릴리스와 동일 SemVer
- 테넌트 프로비저닝: 관리자 API로 수 분 내 개통, 블록 토글 = 요금제 변경
- 미터링: 오디오 처리 시간·세션·시트 단위 계측 → 청구 export
- GPU 서빙 풀: STT/SLM/sLLM 워커 풀을 테넌트 공유(오토스케일), Enterprise는 전용 풀 옵션

## 7. 관측성과 원격 지원

- OpenTelemetry 표준. SaaS는 중앙 수집, 온프렘은 Prometheus/Grafana/Loki 번들 (CORE-ADM에 GPU 자원 모니터링 포함)
- 온프렘 장애 지원: **진단 번들 export** — PII 제거된 로그·메트릭·설정 스냅샷을 파일로 추출해 반출 절차로 전달
- 품질 대시보드: STT 신뢰도 분포, 팝업 지연 p95, 팝업 채택률, 요약 편집률 — 온프렘 동일 제공

## 8. GS인증 / 조달 대응 (공공 패키지)

- 회의록 패키지(B)는 GS인증 취득 → 나라장터 등록으로 반복 판매 체계 구축
- 인증 대상 형상은 블록 번들 버전으로 고정 관리(인증 형상과 릴리스 형상 일치 추적)
